## 三、谨慎退级与停机规则

### 3.1 原规则与新规则

| 项目 | C1 原规则 | v0.7 |
|---|---|---|
| 退级依据 | 64 回合窗口的 EMA | 完整正式评估 |
| 新难度适应期 | 无免退级保护 | **1000 次更新** |
| 退级条件 | EMA 失败≥40%或成功≤20%，连续两窗 | 连续三次完整评估严重低成功，且无明显改善 |
| 最低子级停机 | EMA 失败≥80%，连续四窗；宏阶段≥200更新 | 同一新代训练≥1000更新后，满足新的三次评估条件 |
| 训练 EMA | 驱动 D/L 退级、停机 | 保留诊断，不再驱动上述决策 |

### 3.2 保护期定义

对 D25、D22、D20、L12、L20、L40：

- 从进入该子级的新 generation 开始累计实际完成的 PPO 更新。
- `generation_updates < 1000` 时，禁止因课程表现退级或触发最低子级停机。
- **1000 指训练更新，不是回合数、窗口数或整个 D 阶段累计量。**
- 中断恢复继承计数，不重新获得保护期。
- 真正切换子级、生成新 generation 后重新计算保护期，但已消费的子级预算不清零。
- 本次从 4817 迁入 v0.7，也建立新 generation，并适用该保护期。

保护期不阻止表现良好的策略正常晋级：若满足原来的两次有效完整门禁，可提前进入下一难度。

保护期不豁免预算、原有保持集退化、原有停滞诊断、数值/资源/监控故障和用户停止指令。单回合失败仍正常终止并重置。

### 3.3 正式评估的退级判定

每次 validation 仍为三档速度各 20 例，共 60 例。定义：

\[
S_i=\sum_{\text{三档速度}}\mathrm{case\_pass\_count}
\]

仅接受满足以下条件的评估：

- 当前模型、当前 phase/substage/generation。
- 原有正式 validation，完整 60 例。
- 首回合记录完整且哈希校验通过。
- `generation_updates ≥ 1000`。
- 同一评估事务只消费一次。

**严重低成功：`S_i ≤ 12`，即总成功率不超过 20%。**

算法固定如下：

1. 保护期内不积累退级队列。
2. 合格评估中 `S_i > 12`：清空低成功队列。
3. `S_i ≤ 12`：加入队列，仅保留最近三次连续低成功评估。
4. 三次评估必须属于同一 generation，且为相邻的正式评估时点，相隔各 100 更新。
5. 队列满三次时，计算改善量 `Δ=S_3−S_1`。
6. 若 **`Δ≥6`**，视为至少改善 10 个百分点：本次不退级，继续观察。
7. 若 **`Δ<6`**，触发一次谨慎退级或最低子级停机。

示例：

| 三次总成功数 | 决策 |
|---|---|
| 0、0、0 | 退级 |
| 12、12、12 | 退级 |
| 0、3、6 | 有明显改善，不退级 |
| 0、6、12 | 有明显改善，不退级 |
| 0、13、0 | 中间评估打断低成功连续性，不退级 |
| 20、25、30 | 未达到晋级标准，但继续当前难度 |

不把评估异常、缺失案例或损坏证据当成“0 成功”。此类问题走工程异常处理。

正常情况下，进入新代后最早约 **1200 次更新**才可能满足三次退级检查：1000、1100、1200；若与全局 100 更新评估边界不对齐，则顺延。

### 3.4 退级目标和最低子级停止

- D20 → D22。
- D22 → D25。
- L40 → L20。
- L20 → L12。
- D25、L12 已是本宏阶段最低子级，不跨阶段退回。

D25/L12 若满足上述完整三次条件，触发：

- 状态：`curriculum_stalled`。
- 原因：`persistent_low_validation_success`。
- 保存三次完整评估、成功数、改善量、generation 更新数和 checkpoint。

**删除 v0.7 中 D/L 对旧 `F_EMA≥0.8` 最低停机条件的调用。**不得同时保留新旧两套条件，否则旧逻辑仍会提前停机。

### 3.5 晋级和预算优先级

晋级标准保持：

- 三速各 20 例，每档至少 **18/20**。
- 同一 generation 连续两次有效完整门禁。
- 保留原“新 generation 至少 100 更新才计入晋级资格”的要求。
- 4300 等历史通过记录不能用于新版本当前资格。

同一边界的课程处理：

1. 已完成 PPO 的费用先提交。
2. 完成到期评估与证据持久化。
3. 依原规则处理用户停止、工程异常和保持集等独立停止条件。
4. 根据当前 validation 判断晋级；未晋级时判断新退级条件。
5. 最后执行原有预算判定。

全局上限不得因晋级而越过；预算不足不能自动扩容。
