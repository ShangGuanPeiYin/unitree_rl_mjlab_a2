## 1. v1 的问题与 v2 的修正（Q037 §3 第 1 条）

v1（`logs/a2_v09/s2/q036_verify/recompute_s2_0_top.py`）用 `foot_on_platform` + 聚合 `foot_normal_force` 逐帧计数，且 `feet_safe` 只在帧级 `all(safe)` 使用。冻结实现（`src/tasks/velocity/v07/events.py:229-255` 调 `platform_candidate`，`:257-268`）的实际语义是：

- 逐足候选 = **平台 geom 的顶面法向力 > 5 N** ∧ **该足在 0.042 m 内缩平台内** ∧ tile>0；
- 逐足 `support_count` 仅在**同一 surface/surface 同 tile** 上连续累加，`current_support = count≥2`；
- `recent = step − last_support_step ≤ 50`；
- 帧级 `current` = 四足均 safe ∧ ≥2 足当前支撑 ∧ 四足均 recent ∧ `body_x ≥ front+0.8` ∧ `|body_y| ≤ 0.20` ∧ 无失败；
- 连续 5 帧 `current` 锁存，失败同帧优先。

v2 从原始 trace 精确重建：

1. **平台 geom 的识别**：terrain geom 名为全局 `terrain_<geom_id>`。单个 N40 tile 的 box 顺序为 `ground, tread_1..tread_40, platform`（N+2=42 个），故 `offset = min(观测到的 terrain id)`（出生即接触 ground）且 `platform_id = offset + N + 1`。窄台 trace 观测到 id 1..42（offset=1，platform=42）；宽台观测到 43..84（offset=43，platform=84）。例：s=1558 时 foot 3 的力为 `terrain_41=118.5 N`（tread_40，bounds 7.8–8.0）与 `terrain_42=121.5 N`（platform，bounds 8.0–28.0），聚合值 240.0 N；原实现只取 platform 的 **max**，不是聚合和。
2. **逐足平台力** = `contact_pairs` 中 `geom == platform_id` 的力之和（该 tile 仅一个平台 geom，与 `platform_candidate` 的 max 等价）。
3. **逐足 safe**：`feet_xy` 为世界坐标，`feet_local = feet_xy − frame_origin_world`；`front+0.042 ≤ x ≤ front+length−0.042`、`|y| ≤ width/2−0.042`（与 `feet_safe_platform` 一致）。
4. **机体坐标**：`base_xy` 已是 tile-local（`s2_physics._frame` 用 `root_link_pos_w − origin`）；v1 额外减去了 spawn y（本例为 0，未改变结果），v2 直接用 `base_xy[1]`，与 `|body_y|≤0.20` 的原定义一致。
5. **同 surface/tile 持久**：一个 tile 内平台 geom 唯一、tile 恒定，故 `surface_ids` 恒定，`same` 等价于“该足连续 valid”；已在 `MANIFEST.json.rule` 与脚本注释中记录。
6. **失败优先**：`current` 与事件都要求当帧 `~failure`；遇到失败帧即停止重算（不再产生事件）。
7. **时基**：全部在 trace 采样帧 `s`（原始行 `step`）计算；报告约定 `r=s+1`，仅在输出 `report_event_step_minus1` 时换算一次。
8. **post-reset 行剔除**：旧 writer 有的行缺 `post_reset` 标志，v2 用“failure/terminal 行相对上一物理样本的位姿跳变 > 0.5 m”识别自动 reset 行（如 case 0：`9.195→−1.049`），真实终止物理帧保留为 `last_valid_pose_step`。

### 1.1 坐标与失败优先复核

- 世界/局部坐标：`feet_xy` 为世界坐标，减 `frame_origin_world` 后与平台矩形比较；`base_xy` 已是 tile-local（`s2_physics._frame` 用 `root_link_pos_w − origin`）。逐例复核了四足局部 x/y 与 `front`、`front+length`、`width/2` 的关系。
- 代表帧（case_id 0，s=1578，安全登顶帧）：`body=(8.8715, −0.0190)`（局部），四足局部 x = [8.988, 8.897, 8.412, 8.566]，y = [0.177, −0.246, 0.133, −0.255]；平台内缩边界 x∈[8.042, 27.958]、|y|≤0.358 → 四足全 safe；平台力 [181.7, 149.3, 0, 0]，当前支撑 [T,T,F,F]（≥2），连续计数 5 → 锁存。
- 失败优先：逐例要求事件帧 `~failure` 且失败事件严格晚于安全登顶；窄台 15/15 `failure_priority_ok=True`。若失败与事件同帧，`current` 与事件均被抑制（脚本遇失败帧即停止）。

### 1.2 等价性证明结果

- 窄台 15 例：v2 精确事件步 == v1 代理事件步（15/15 `proven_equivalent`）。
- 候选差异审计：15 例中共 **84 帧**出现“逐足候选 strict ≠ v1”（例如 case 0 的 s=1532–1561 有 6 帧），说明两者并非恒等；事件步仍相同，故 v1 的 25–38 帧结果**被证明未变**，不是未经验证的代理。
- 宽台 15 例：两种方法均无事件，且 `max_body_x < 8.8` 提供几何证明（不依赖接触/力）。
- 未证明/未覆盖：0 例 `proxy_reconstruction_unverified`；plane 分支与其它任务不在本件范围。
